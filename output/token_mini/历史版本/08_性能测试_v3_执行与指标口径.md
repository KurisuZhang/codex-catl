# 08 性能测试执行与指标口径

## 本轮更新：直接跑 0% / 90% 命中

**不需要另外下载两套数据集。** 本方案使用 EvalScope `random` 生成两种前缀结构，压测同一 vLLM 或 SGLang 的 OpenAI 兼容 `/v1/completions` 服务。90% 指输入 token 中的复用比例，而非90%的请求曾命中过缓存。

### A. 固定版本并检查条件

在独立压力机安装EvalScope并记录版本，确认 `evalscope perf --help` 含 `--tokenize-prompt`、`--prefix-length`、`--warmup-num`。tokenizer必须与服务模型一致，服务支持token-ID列表输入。上下文容量至少覆盖12800输入加128输出；容量不足时按90/10比例缩短且结合缓存块对齐。随机token输入只用于性能测试，不用于回答质量测试。

当前核验的源码将prefix-length加到prompt-length上。例如11520+1280=12800。文档存在不一致表述，必须在安装版本上用小批请求确认 `prompt_tokens=12800`，不要直接套其他版本的参数语义。

### B. 服务端切换缓存模式

保留07中已跑通的模型、精度、硬件和并行参数，只修改prefix缓存选项，在隔离测试实例上重启：

| 服务 | 严格0%基线 | 90%目标组 |
|---|---|---|
| vLLM / 兼容的Ascend版本 | `--no-enable-prefix-caching` | `--enable-prefix-caching` |
| SGLang | 添加 `--disable-radix-cache` | 移除此禁用项，核验radix缓存开启 |

这里关闭的是跨请求前缀复用，不是关闭单个请求解码所需的KV缓存。模型/后端若不支持前缀缓存，不能执行90%命中实验，必须在结果中标明该组合不具备此测试条件。外部KV缓存或其他复用层也应关闭或固定并注明。

如果要测“缓存开启但没有命中”的额外场景，保持缓存开启，清理隔离实例缓存后跑独立前缀并确认命中≈0。该组有缓存查找开销，应与严格关闭组单列。不能靠prefix-length=0保证绝对0%，因为可能有前缀碰撞或历史残留。

### C. 设置压测端变量

```bash
export URL='http://<服务IP>:8000/v1/completions'
export MODEL='<服务返回的模型ID>'
export TOK='/data/models/<匹配tokenizer目录>'
```

SGLang使用实际服务端口。示例针对隔离的无鉴权内部测试端点，有鉴权时须补充安装版本支持的凭据参数。

### D. 0%基线

确认服务已关闭prefix缓存后：

```bash
bash 08_缓存压测.sh zero 16
```

该脚本配置 `prefix-length=0`、`min/max-prompt-length=12800`，生成独立输入。预热64请求不计入工具性能汇总。正式2000请求，输出上限128，记录实际输出量。

### E. 90%目标组

将服务重启为缓存开启状态后：

```bash
bash 08_缓存压测.sh hot90 16
```

配置 `prefix-length=11520`、`min/max-prompt-length=1280`，总输入12800。工具在同一次运行中生成一段公共前缀，预热与正式请求共享此前缀、后缀不同；不要通过另开一次随机运行来代替预热，也不要在预热结束后清缓存。当前实现为预热和正式阶段生成不同条目避免循环重放。

固定单副本便于控制。如果有多个服务副本，必须逐个预热或验证路由命中情况。90%仅为构造目标：块对齐、缓存淘汰、特殊token、随机后缀偶然复用均会改变实际比例。

### F. 核验并扫并发

先读取正式请求的实际 `cached_tokens` 与 `prompt_tokens`，计算Σcached/Σprompt。缺少请求级数据时可使用隔离服务端计数器的正式窗口增量，必须排除预热并记录其是否含失败请求；无法剔除预热的计数不能直接称正式90%。工具排除预热不意味着Prometheus计数自动排除预热。

接受范围可预先设为89%～91%（项目建议），超出时排查实际输入长度、cache block、缓存容量、模型缓存支持及路由。报告真实命中率，不能将结果强行写成90%。

依次将脚本第二个参数改为1、2、4、8、16、32、64……，每档使用新的隔离缓存状态并预热。脚本并发>64时自动增大预热请求数。2000请求只是起始数量，若未覆盖所需稳态时长，设置 `REQUEST_COUNT` 增大，不可宣称已测满5分钟。每档采集第二页全部指标，并按SLA判定最大可用并发。脚本不会替你自动切换服务缓存配置，也不会将构造比例当作实测值。

### 原生工具的替代能力

vLLM自带 `prefix_repetition` 数据集，支持 `--prefix-repetition-prefix-len`、`--prefix-repetition-suffix-len`、`--prefix-repetition-num-prefixes`；SGLang自带 `generated-shared-prefix` 合成数据集。均可构造共享前缀，不需要外部下载数据。本页统一采用EvalScope，避免同时展示多套长命令。真实业务复测时再导入业务数据集，并核对模板后的实际token与前缀。

源码依据：[EvalScope random实现](https://github.com/modelscope/evalscope/blob/main/evalscope/perf/plugin/datasets/random_dataset.py)、[参数与预热](https://github.com/modelscope/evalscope/blob/main/docs/en/user_guides/stress_test/parameters.md)、[vLLM合成前缀数据](https://docs.vllm.ai/en/latest/benchmarking/cli/)、[SGLang压测指南](https://github.com/sgl-project/sglang/blob/main/docs/developer_guide/bench_serving.md)。查询2026-09-16。仅完成脚本语法检查，未连接项目设备压测。

# 性能测试：执行模板与指标口径

本文件为测试方案，尚未执行。工具安装在独立压测机，固定工具版本并保存 `--help`、完整命令和环境信息。服务镜像、模型 revision、量化和并行参数由07部署流程冻结。以下地址、模型ID及tokenizer目录是占位项，执行前替换。

## 1. 先定义成功标准

填写 P95 TTFT、P95 TPOT、P95 E2E、成功率与超时阈值。未定义阈值只能报告饱和点，不能报告“满足SLA的最大并发”。一个模型在不同输入输出长度、缓存比例和卡数下分别有自己的最大可用并发。

每个测试配置记录：卡型/单卡显存/卡数、模型与量化、引擎/镜像版本、TP/DP/EP、上下文、输入长度/输出长度、KV缓存与prefix cache配置、工具版本和随机种子。示例长度组合为输入1024/8192与输出128/512 token，均属于测试设计，需按业务目标选取，不是模型能力承诺。

## 2. 三种工具的起测命令

先启动服务并验证健康接口和流式接口。工具版本不同参数可能变化，按冻结版本 `--help` 核对。以下为无命中随机负载的起测模板，缓存命中专项需另构造数据集，不能用随机模板宣称已测缓存吞吐。

### vLLM 自带工具

```bash
vllm bench serve --help
vllm bench serve \
  --backend openai-chat \
  --base-url http://<服务IP>:8000 \
  --endpoint /v1/chat/completions \
  --model '<服务模型ID>' --tokenizer '<本地tokenizer目录>' \
  --dataset-name random --random-input-len 1024 --random-output-len 128 \
  --num-prompts 1000 --request-rate inf --max-concurrency 16 \
  --save-result --result-dir ./results/vllm-c16
```

`--request-rate inf` 与并发上限结合，持续补充请求。`1000`为请求数示例，不能保证测量持续5分钟，需根据速度增加请求量。若服务/工具支持忽略EOS，可固定输出长度；否则记录实际输出长度分布并在对比时对齐，禁止使用128作为实际生成量。

### SGLang 自带工具

```bash
python -m sglang.bench_serving --help
python -m sglang.bench_serving \
  --backend sglang --host '<服务IP>' --port 30000 \
  --dataset-name random --random-input-len 1024 --random-output-len 128 \
  --num-prompts 1000 --request-rate inf --max-concurrency 16 \
  --output-file ./results/sglang-c16.jsonl --output-details
```

该模板针对SGLang服务的原生后端。跨引擎比较时应统一协议、数据和长度，或用下方EvalScope统一压测OpenAI兼容接口。不能默认两个工具随机数据和分位数统计完全相同。

### EvalScope：统一接口复测

```bash
evalscope perf --help
evalscope perf \
  --url 'http://<服务IP>:8000/v1/chat/completions' \
  --model '<服务模型ID>' --api openai --stream \
  --parallel 16 --number 1000 \
  --dataset random --tokenizer-path '<本地tokenizer目录>' \
  --min-prompt-length 1024 --max-prompt-length 1024 \
  --min-tokens 128 --max-tokens 128
```

有鉴权时按工具支持的方法注入凭据，不写入公开报告。保存逐请求结果、工具汇总和服务端指标快照。实际长度仍以服务返回/匹配tokenizer统计为准。

## 3. 构造缓存专项

- 无命中组：保持输入长度，使用不同token前缀；隔离测试实例按所选引擎支持方式重置缓存，或使用互不重叠前缀。正式统计时实际命中应接近0。关闭缓存的结果应单列，不能与“开启缓存但未命中”混同。
- 命中组：固定公共token前缀，先在计时外预热，再发送相同前缀与不同后缀。保持完整输入长度和输出长度与无命中组一致。缓存按块匹配，tokenizer、chat template、系统提示、路由和副本都会影响实际命中。
- 混合组：按业务比例混合上述请求。记录实测命中率，而不是把设计比例当作命中率。

使用工具支持的自定义数据集格式导入相同提示集合。不要将预热请求加入吞吐分子，计数器在预热后取基线。每次并发档切换后重新核验缓存状态，避免前一轮残留放大结果。服务的实际 cached_tokens 字段或对应版本的计数器缺失时，缓存吞吐标为“不可得”，不能用前缀长度推算。

## 4. 扫并发并寻找边界

1. 独立压力机直连推理服务，先测并发1，确认压力机CPU/网络无瓶颈。
2. 依次测1、2、4、8、16、32、64……。每档先预热，再测至少5分钟稳态；示例时长可按样本量加长。
3. 同时观察配置并发、压测端实际在途请求、服务端运行/等待请求、吞吐和P95延迟。
4. 吞吐基本不再上升而队列/延迟增加，标记饱和区；达到SLA失败、错误或OOM则停止继续提高。
5. 在最后通过和首次失败的档位之间细扫。临界档重复3次，使用保守通过值；随后做30分钟持续验证。
6. 另外按真实到达率测试，确认队列不会持续积累。最大并发不等于可长期接收任意到达率。
7. 经MASS复测相同负载，区分引擎能力和平台网关开销。

最终报告同时列出饱和并发和最大可用并发。若只测到64且仍达标，应写“至少支持64，本轮未找到上限”，不能写“最大64”。

## 5. 指标口径

统一请求集合和计时窗口：推荐正式请求全部完成或超时后结束，窗口包含尾部排空，排除预热；所有吞吐均使用同一个T（秒）。固定稳态事件窗口是另一种方法，采用时需说明跨边界请求处理，不能混用。

| 指标 | 定义 |
|---|---|
| TTFT | 首个有效输出token时刻减发送时刻，ms，P50/P95/P99；含网络、排队和prefill，不等于纯prefill计算时间 |
| TPOT | 每请求(末token时刻－首token时刻)/(实际输出token数－1)，ms/token；输出≤1时不计算，然后对请求值取分位数 |
| E2E | 请求发出到请求完成的总时延，ms，记录P50/P95/P99 |
| 无命中Prefill吞吐 | 成功请求Σ(输入token－实际命中token)×60/T，token/min |
| 命中Prefill吞吐 | 成功请求Σ实际命中token×60/T，token/min，表示复用服务量 |
| Decode吞吐 | 成功请求Σ实际输出token×60/T，token/min |
| 命中率 | Σ实际命中输入token / Σ输入token |
| 可靠性 | 成功数/总请求数、超时数、错误数与类型、提前结束数 |
| 资源 | 各卡峰值显存、设备利用率/功率、网络、运行及排队请求数 |

保留发送、首有效token、末有效token、完成时间与实际token数。空SSE块/角色块不是首token，一个SSE块可能有多个token，不能将块数当token数。逐token间隔ITL与逐请求TPOT分布不同，工具字段必须核对。

优先从同一批请求的usage与cached_tokens对账。若用服务端计数器，核对名称、单位、重启、是否包括失败/预热/其他流量，以及跨副本汇总规则；这种全流量口径必须另列，不能与成功请求口径混算。

总输入服务吞吐＝无命中＋命中，缓存命中不是重新计算的prefill产能。混部测试得到端到端服务吞吐，不能直接认定为独立Prefill/Decode集群极限。换算卡均token/s时除以60及实际占用卡数，仅是同配置平均；收入分析不能让同一批混部卡重复承担独立P/D产能。

## 6. 结果文件

配套CSV每一行对应一次测试，不填虚构结果。请求级原始JSONL单独存放并关联run_id。性能报告绘制并发—吞吐、并发—P95 TTFT/TPOT、并发—成功率曲线，标出缓存场景及SLA阈值。
