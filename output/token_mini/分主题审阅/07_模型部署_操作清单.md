# 07 模型部署操作清单

本清单用于部署准备与实施。尚未在项目服务器上执行。尖括号内容必须替换，具体驱动、镜像 digest、模型 revision、IP 和 MASS 接口尚待现场确认，不能把示例当作已验收脚本。

## 1. 冻结部署输入

记录模型仓库、来源平台、固定提交/版本、许可证与访问授权、权重格式、目标卡型和卡数、模型上下文、并发、最大输出长度。确定质量基线和性能目标。910B 示例选择 Qwen3.8-27B 的 A2 路径；T4 的文本引擎候选为 vLLM / SGLang / Ollama / llama.cpp，按具体模型、量化格式、SM75 算子支持和实测性能选择。下面以 Qwen3.5-9B GGUF Q4_K_M＋llama.cpp 演示一条路径，不是唯一方案。

## 2. 节点准备

核对 CPU 架构、OS/内核、内存、系统盘和模型盘剩余容量。模型盘需额外容纳缓存、解压/转换中间结果和镜像。配置时间同步、DNS、业务 IP、管理访问、服务端口、节点间端口、存储挂载和读写权限。记录拓扑与设备编号。

```bash
uname -m
cat /etc/os-release
df -h
free -h
nvidia-smi     # T4 节点
npu-smi info   # 910B 节点
```

安装与硬件、内核和镜像兼容的驱动/固件，需重启时先排空设备。重启后复查卡数、健康状态和版本。T4 安装匹配的容器运行时及 NVIDIA Container Toolkit；910B 按官方方案配置 Ascend 容器设备与驱动库挂载。使用 K8s 时再核验 Device Plugin 与设备资源，不将 K8s 当作首次模型验通前置。

## 3. 下载模型

在独立 Python 环境安装并记录下载工具版本，受限仓库先取得访问权限。下载凭据只用于下载环境，不写入镜像或共享文档。

```bash
python3 -m venv /data/download-venv
source /data/download-venv/bin/activate
python -m pip install huggingface_hub modelscope
python -m pip freeze > /data/download-tools.txt
hf auth login  # 仅需认证时执行

# 二选一；分别确认平台上的仓库 ID 与固定 revision
hf download Qwen/Qwen3.8-27B \
  --revision '<HF固定提交>' --local-dir /data/models/qwen38-27b

modelscope download --model '<ModelScope仓库ID>' \
  --revision '<该平台固定版本>' --local_dir /data/models/qwen38-27b
```

T4 从 `unsloth/Qwen3.5-9B-GGUF` 核对 Q4_K_M 对应文件名和分片集合。多模态使用时补齐匹配的视觉投影文件。只下载选定格式及必需组件，避免下载仓库中所有量化变体。HF 和 ModelScope 同名模型不能默认提交一致。

## 4. 文件与量化校验

核对 safetensors 索引引用的每一片、config、tokenizer 及 chat template，检查下载是否完成，排除占位文件或损坏文件。GGUF 检查全部分片和对应投影文件；Wan 补齐文本编码器、VAE 等管线组件；YOLO 核对权重及类别映射。

HF 可按当前 CLI 帮助使用 `hf cache verify` 对本地目录进行源文件校验。SHA256 自建清单用于分发一致性，不能单独证明下载来源可信。量化或格式转换仅在所选引擎要求时执行，记录工具版本、校准集、参数和原始权重版本，转换后再次做质量比较。

Linux 分发清单示例：

```bash
cd /data/models/qwen38-27b
find . -type f ! -path './.cache/*' -print0 | sort -z | xargs -0 sha256sum > /data/qwen38-27b.sha256
```

## 5. 分发模型与镜像

将模型放入共享只读目录，或复制到每个节点同一路径。传输后在目标目录运行 `sha256sum -c /data/qwen38-27b.sha256`，清单也需同步。禁止把不同版本权重混在同一目录。

镜像按官方模型指南选择 CPU 架构、A2/T4 后端和版本。拉取后记录 digest，发布时固定 digest。容器挂载模型为只读，日志和编译缓存为独立可写目录；配置所需设备、驱动库、共享内存、网络模式和端口。按对应硬件指南配置容器，不能将 T4 的 `--gpus` 参数直接用于 Ascend。

## 6. 容器内检查

再次运行设备查询，确认数量、编号与宿主机一致。检查模型目录可读、日志可写，框架和引擎可导入，版本符合配套要求。若失败先修复设备透传、驱动库或版本问题，再启动模型。

## 7. 单机启动

T4 先选择引擎：vLLM / SGLang 须核验该模型与量化格式的 T4 算子支持；Ollama / llama.cpp 也是候选，仍需验证质量、显存和并发性能。选定后按对应引擎固定版本的命令启动，不在同一实例中叠加多个引擎。YOLO / Wan 保持任务独立管线。

910B：采用下方官方 Qwen3.8-27B 指南的 **A2** 配置，保存完整启动脚本，替换模型路径、服务名和监听地址。量化权重与 `--quantization` 必须匹配；并行度、注意力实现、附加参数按同一指南版本，不从不同 release 拼接。先用低并发、较短上下文，记录启动日志和逐卡显存。

T4：在已验证支持 Qwen3.5 与 SM75 的 llama.cpp CUDA 构建内，启动示例：

```bash
llama-server -m '<GGUF文件绝对路径>' -ngl 99 -c 4096 \
  --host 0.0.0.0 --port 8000
```

`-ngl 99` 尝试将模型层放到 GPU，须观察实际卸载层数与内存。4096 是起测值。需要视觉输入时配置匹配的投影模型。监听所有网卡仅供受访问控制的内部服务使用。对外访问通过鉴权网关。

## 8. 接口验证

```bash
curl --fail http://127.0.0.1:8000/health
curl --fail http://127.0.0.1:8000/v1/models
curl --fail http://127.0.0.1:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"<上一步返回的模型ID>","messages":[{"role":"user","content":"请用一句话介绍你自己。"}],"temperature":0,"max_tokens":128}'
```

配置服务鉴权时补充相应 Authorization。等待首次加载/编译完成再判断健康状态。检查非空回答、正确模型 ID、停止条件和报错；将 `stream` 设为 true 并使用 `curl -N` 验证流式响应。多模态另测图片输入。YOLO/Wan 以任务服务接口验证，不套用聊天端点。

## 9. 双机与多副本

仅对需要跨机的模型执行。核对两节点镜像 digest、模型 SHA256、网卡映射及 HCCL 版本。先做链路连通与官方多机通信测试，再运行多机模型。配置主节点地址、各节点 IP/rank、TP/DP/EP、节点间端口和超时，按具体指南顺序启动。检查所有 worker 就绪和逐卡显存。GLM-5.3/DeepSeek-V4.1-Flash 的双机方案仍需专项验证，不能直接把四机命令改为两机。

T4 小模型优先做独立单卡副本，分别配置端口和设备，避免重复占用同一卡。副本扩展后复测路由和负载分配。

## 10. 验收

固定题集与模型/量化前基线比较输出质量，再逐步扩大输入、输出和并发。记录实际负载、成功率、错误、逐卡峰值显存、TTFT、TPOT、吞吐及持续运行结果。YOLO 固定分辨率/批量，测检测质量和延迟；Wan 固定分辨率/帧数/步数，测视频质量及耗时。任何显存不足、质量下降、通信错误都应回到对应步骤修复并复测。

## 11. MASS 接入

按现有平台文档填写：服务地址、模型名、协议、上游鉴权、超时、限流、路由权重与健康检查。平台密钥与上游密钥分开管理。用用户侧 API Key 发起端到端请求，验证普通/流式响应、取消和失败请求、用量汇总及计费口径。明确输入/输出/缓存 token 的计数来源；无法取得的字段不能凭估计写成真实用量。MASS 版本和接口尚未提供，具体菜单、API 路径和配置字段待实际文档确认。

## 12. 发布、监控与回退

按平台要求使用 K8s 或进程托管，配置资源、健康/就绪探针、启动宽限、重启策略、日志轮转、监控和告警。小流量验证后逐步增加路由权重。演练节点重启、副本退出、失败告警和恢复。保留上一版权重/镜像/配置；回退时先切换路由、排空请求，再停新实例，重新验证平台请求和计量。

交付：模型清单、镜像 digest、节点/端口表、启动脚本、平台配置、质量/性能报告、运行日志及回退步骤。
